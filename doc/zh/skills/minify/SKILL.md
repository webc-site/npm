# JS 体积优化（minify 之后）

优化对象是构建产物（本仓库 `./minify.js` 的输出），不是源码字节数。每次优化前后
记录 raw 和 gzip 两个体积，两个都要看；对外展示徽章用的是 gzip。

## 工作流程

1. 跑 `./minify.js` 记录基线（raw + gzip）。
2. 每次只改一类优化点，改完立刻 `./minify.js` 对比，有收益才保留。
   不要凭直觉判断哪个写法更小，实测经常和直觉相反（见下文案例）。
3. `./test.sh` 收口：格式化、lint、构建、对比测试一次跑完。
4. 对比测试是兼容性契约。结构层面的复用被测试否决时果断回退，不要试图连测试一起改。

## 压缩器行为认知（决定手法是否有效）

1. 标识符不占体积。mangle 之后 const 名、变量名全部变成单字符，省着写名字、
   合并声明没有意义。真正占体积的是字符串字面量、数字、以及代码结构：
   回调定义、闭包、调用点的数量。
2. 常量折叠。压缩器会把 `const A = "x"; A + "y"` 折叠成完整字面量。公共子串拆成
   const 再直接拼接，输出里会重复内联，raw 变大；但 gzip 压重复字符串极强、
   压回调代码弱，所以「const 直接 +」通常 gzip 更小。实测案例（三种样式字符串）：
   用 `.map` 回调间接拼接防止折叠，raw 8.791 KB / gzip 4.636 KB；
   const 直接 +，raw 8.866 KB / gzip 4.610 KB。gzip 优先时后者胜。
3. 想在 raw 层面去重，只能用运行时间接（map 回调参数、函数调用参数），折叠不掉，
   但要付回调定义的开销。两种写法没有绝对胜负，必须两指标实测后裁决。
   注意方向随层次而变：数据层的重复内联 gzip 反而受益（const 直接 + 更小）；
   代码层的函数合并（如 mover/munder 抽成工厂）省 raw，但重复模式被参数化打散，
   gzip 会微涨。两头都要实测。
4. 查表驱动是体积友好的结构：键是必要数据省不掉，值用短数组 `[type, ...]`，
   type 用数字常量，内联后就是单字符字面量。

## 手法清单（均已实测验证）

1. 重复后缀移出数据。宽度、单位这类后缀不要写进每条数据，数据源写数字，
   构建查表时统一拼接（`v + "px"`），渲染端保持 `' width="' + val + '"'`，
   不引入任何运行时类型判断。
2. 同义命令归一。行为完全一致的一组命令（如 `\textrm/\textbf/...`），删查表同义键，
   两种落点：行为差异影响词法扫描的，在 lex 层统一改写为规范名（`\text` 族）；
   只影响查表的，在查表处回退（`CMD_MAP[name] || CMD_MAP[name.replace(/^wide/, "")]`，
   `\widehat` 族，未知名经 replace 后仍会走后续检查，不会误伤报错路径）。
3. 转义用数字字符引用。`"&#" + m.charCodeAt(0) + ";"` 代替实体名三元链，
   `&#NN;` 本就是合法 XML/HTML。前提是下游归一化兼容，测试确认过再用。
4. 死槽位填空。数据流里确认无人读取的槽位填空串，不要填占位字符。
5. 副作用循环用 `for..of`，不用 `[...s].map`，省掉 spread 和 map 回调外壳。
6. 短形式择优靠实测，别想当然。`replace(/ /g, x)` 其实比 `replaceAll(" ", x)` 短。
7. 公共子串拆 const 复用，源码不重复书写，产物交给压缩器决定内联形态。
8. 未被入口引用的导出模块不影响 bundle（摇树），但会挂 knip 未使用告警，留意即可。

## 顶层设计审查点

1. 表示层优先于控制流：token 流用平铺数组 `[type, val, ...]`，节点用 `[type, ...]`，
   数字 type 码配查表分发；优化空间主要在数据表和同义归一，不在逻辑本身。
2. 多键共闭包（`hat: k("^"), widehat: k("^")`）优于分支；但键归一要算账，
   「正则/前缀改写的运行时代码」贵过「三四个键」时不划算，就不做。
3. 合并节点类型前先看语义是否由消费上下文决定。案例：fence 和 brace 组渲染逻辑
   完全相同，合并 TYPE_LEFT_RIGHT 进 TYPE_GROUP 后 2 例测试失败——
   顶层渲染上下文里 fence 要保留 `<mrow>` 包裹而 brace 组不要，只能回退。
4. 渲染端以「无运行时类型判断」为原则：单位、后缀在数据构建期消解，不在使用处补。

## 一句话原则

源码保持清晰、数据用数字常量、复用交给查表和 const；产物大小靠实测说话，
测试是唯一裁决标准。
